# NeoMods 26.3 (Mod Menu 統合版 / Gradle なしビルド)

Gradle・Loom・gradlew は不要。**JDK 25 の `javac` と `jar` だけ**でビルドします。

    build.bat         # Windows → NeoMods.jar (build.bat と同じ階層。途中の生成物は bin/ に出る)

Minecraft 26.3 本体(Mojang 公式の無加工 jar)は `libs/` に同梱済みです。Fabric API は一切不要です。
Fabric Loader / Mixin / Guava など残りは、Fabric Loader 0.19.5 を導入済みの
`.minecraft/libraries` から自動で拾います (別の場所は `MC_DIR` で指定。詳細は `libs/README.txt`)。

## ソース構成
パッケージは最大でも `neo.menu.<名前>` (3 階層)。小さなパッケージは統合済み。

- `src/neo/java/` … **ローダー非依存の本体** (Fabric の型を import しない)
  - `neo.menu` … 入口の接続 (`ModManagerCompat` / `ModManagerEventHandler`) 
  - `neo.menu.{config, gui, mod, service, util}` … 設定 / 画面 (一覧・ボタン・描画を含む) / Mod モデル / サービス / 共通部品
  - `neo.{spawnerinfo, tooltip, advancements, skinlayers, event, util}` … Spawner Info / EnchantToolTip / イベント置き場 / 画面ヘルパ
  - `com.terraformersmc.modmenu.api` … **Mod Menu API 互換** (`ModMenuApi` / `ConfigScreenFactory` / `NullScreenFactory`)。他の Mod が `"modmenu"` エントリポイントで実装するときの名前そのものなので変更不可。`FabricPlatform#loadIntegrations` がこれで他 Mod の設定画面・モドパックバッジを受け取る。jar に入る
  - `eu.pb4…`・`org.jetbrains…`・`org.jspecify…` … 他ライブラリの型の代わりのコンパイル専用スタブ (外部の名前そのものなので変更不可。jar には入らない)
- `src/main/java/` … **Fabric 側の接着部分**
  - `neo.fabric` … エントリポイント (`NeoMain` / `NeoClient`)、`NeoCore`、Fabric アダプタ (`FabricPlatform` / `FabricMod` など)
  - `neo.mixin` … 全 Mixin (mixin 設定は `mixins.neo.json` の 1 本)
- `src/forge/java/` + `src/forge/resources/` … **Forge 版 (Mod Menu 本体のみ)**。`neo.forge` の 5 クラスと `META-INF/mods.toml`。**`build.ps1` は、`libs/forge/` に Forge の jar があるとき (または `BUILD_FORGE=1`) だけ一緒にビルドし、`mods.toml` も同じ jar に入れます**。無いときは Fabric 専用の jar になります (Forge のクラスも `mods.toml` も入らない)。`build.sh` も同じ条件で対応します (Eclipse には含めていません)。
- `src/main/resources/` … fabric.mod.json / mixin 設定 / assets (アセットの名前空間は **`assets/neo/` だけ**: テクスチャ・スプライト・アイコン・lang。名前空間は `neo.util.NeoAssets`)
- 1 パッケージは必ずどちらか一方のルートだけに置く。`src/neo` → `src/main` への依存は禁止
- ローダー固有の機能は `ModManagerPlatform` / `IconSource` / `ModContact` の抽象越しに使い、Fabric 実装は `neo.fabric` に集約
- 両方のソースルートを `build.ps1` / Eclipse が同時にコンパイルします

## Fabric API 脱却の進捗
Mixin(Fabric Loader 同梱)で Fabric API を置き換えていく作業の記録です。
- [x] EnchantToolTip … `neo.mixin.MixinItemStack` (ItemTooltipCallback の代替)。Fabric API 不要
- [x] Mod Menu … `MixinMinecraft`(tick) / `MixinOptions`(キー登録) / `MixinScreen`(`ScreenInternals` を実装)(画面初期化・ウィジェット一覧)。Fabric API 不要
      (補助クラス: `neo.event.NeoClientEvents`, `NeoKeyMappings`, `neo.util.ScreenWidgets`)
- [x] Spawner Info … サーバー tick: `MixinMinecraftServer` / 描画: `MixinLevelExtractor` / 受信: `MixinClientPacketListener` /
      ペイロード登録: `MixinClientboundCustomPayloadPacket`(送受信両側) / 送信: `connection.send(new ClientboundCustomPayloadPacket(..))`
      未導入クライアントへの `canSend` 判定は廃止(常に送信。バニラは未知ペイロードを捨てる)。Fabric API 不要

実行時の依存は `fabricloader` と `minecraft` のみ。jar-in-jar の Fabric API は同梱しません。
`libs/minecraft` は公式の無加工 jar に差し替えました。以前の jar は Loom 加工済みで Fabric API の型を参照していたため、コンパイルに Fabric API の jar が要りましたが、無加工なら不要です。

注意: Mixin 設定は `mixins.neo.json` (新規) と `mixins.modmenu.json`。
この環境には Fabric Loader / Mixin / MixinExtras が無く、Minecraft 実機での起動確認は未実施です。

## 機能の設定 (Mod Manager → 設定)
Mod 名・概要の翻訳は、バニラの言語設定 (いま選んでいる言語) に従います (翻訳の ON/OFF の設定は無く、その言語の翻訳があれば使い、無ければ Mod 自身の名前・説明を出します)。

この Mod が内蔵する機能は、Mod Manager の設定画面で ON/OFF します (設定はバニラの `options.txt` の `neo_` で始まる行に、**既定値から変えた項目の分だけ**保存されます。設定画面の「既定に戻す」ボタンで、画面の項目をすべて既定値に戻せます。戻した項目の行は、保存のときに `options.txt` から消えます)。**既定で ON なのは「進捗画面の拡大」「クリックコマンドの確認を省略」「ズーム」「インベントリを開いても移動」「進捗とインベントリの直接切り替え」「3D スキンレイヤー」「ワールドマップ」と、その目印の自動表示 (構造物と旗で 1 つ)、「F5 を自由視点にする」「サウンドブラウザ」「AFK シネマティック」の計 11 個だけ**で、他はすべて OFF です。

## OFF のときの負荷 (設計)
OFF の機能は、**毎フレーム・毎 tick・サーバー側の処理を入口で打ち切る**設計です。
- エンチャントツールチップ: ツールチップ生成のたびに設定を 1 回引いて即 return (スタック解析・文字列整形は行わない)
- スポナー情報 (クライアント): 全体スイッチ OFF → 毎フレームの Gizmo 収集用オブジェクトも作らず即 return / 受信データは捨てる / 溜めたデータと「最寄りのみ」の選択は破棄 / スポナー走査 (チャンクのブロックエンティティ巡回) もしない
- スポナー情報 (サーバー側): シングル/LAN ホストでは設定 OFF の間、走査・NBT 保存・送信をすべて省く。**専用サーバーはクライアント設定が届かないので従来どおり送信する** (トラフィックはスポナー付きトロッコが近くにあるときだけ)
- 進捗画面の拡大: 進捗画面を開いている間だけ、各数値の差し替え処理が設定を引いて元の値を返す
- コマンド確認の省略: コマンドを送った瞬間にだけ判定。リンク確認の省略: 画面を切り替える瞬間に、その画面がリンクの確認画面のときだけ設定を見る (それ以外の画面は instanceof だけ)

## ワールドマップ (M キー)
`neo.map`。**バニラの地図アイテムを両手で持った見た目**を、そのまま使う地図画面です (独自の絵や形式は持たない)。
- **見た目**: M キーを押すと、バニラの両手持ちの地図 (**両腕・紙の枠・チェッカーの下地・装飾アイコン**) が画面中央に大きく出る (手の描画はバニラの `FirstPersonHandsAndItemsRenderer` そのもの。持ち替えの動き = 手を下げて上げる、も同じ)。左右にボタン・ピン一覧・縮尺バー・ピンの編集欄を並べる。閉じると元のアイテムに戻る。**一人称で描かれるので、開いている間は視点を一人称にし、閉じたら元に戻す。スペクテイターでは使えない** (バニラの手が描かれないため)
- **仕組み**: バニラの地図データ (`MapItemSavedData`) を 1 枚ぶん**装飾の入れ物**としてクライアントの地図に登録し (`ClientLevel#overrideMapData`、バニラの地図パケットを受け取るときと同じ手順)、メインハンドに「その地図を持っている」ことにする (`MixinFirstPersonHandsAndItems`)。オフハンドは空にする (バニラは「メインハンドに地図 + オフハンドが空」で両手持ちにする)。地図の傾き (視線の上下で変わる) は 0 にして常に正面に向ける (`MixinFirstPersonHandsAndItemsRenderer`)。地図の画面上の位置は、バニラの変換を辿って計算する (`HandMapGeometry`、手の視野角は固定の 70°)
- **中身の画像は高解像度 (512×512)**: バニラの地図は 1 枚 128×128 ピクセル固定で、1 ブロック 1 ドットだと見える範囲が 128 ブロック四方しかない。バニラの描画は「地図の画像 = ID で渡されたテクスチャを四角に貼る」だけなので、**中身の画像だけを自前の 512×512 のテクスチャに差し替えた** (`MixinMapRenderer`)。紙の枠・両腕・装飾はバニラのまま。色はバニラの `MapColor` で、同じスケールの地図から 1 ピクセルずつ写す。**見える範囲はバニラの 4 倍の幅** (スケール 0 で 512 ブロック四方、1 ブロック ≒ 画面の 1.6 ドット / スケール 4 で 8192 ブロック四方)。解像度は `HeldMapView.RESOLUTION` で変えられる (大きいほど細かいが、描き直しが重くなる)。**画像の描き直しは頻度を大きく落としている**: 動かしている間は最大でも 0.15 秒に 1 回 (止まったら必ず 1 回追いつく)、止まっているときは 1 秒に 1 回「中身が変わったか」を地図の版で調べるだけ (変わっていなければ画像は触らない)、開いた直後とスケールを変えたときだけ即時。矢印・ピン・クリック位置は「いま画面に出ている窓」を基準にするので、描き直しが遅れてもずれない
- **縮尺**: バニラの地図のスケール 0 (1 ピクセル = 1 ブロック) 〜 4 (1 ピクセル = 16 ブロック)。**ズームは段階で切り替わる** (なめらかな拡大縮小のアニメーションは無い)。動かせるのも 1 ピクセル (= そのスケールの 1〜16 ブロック) 単位。スケールごとに独立したバニラの地図 (蓄積用、128×128) を持ち、その縮尺で表示するときは同じ縮尺の地図を写す
- **地図の蓄積**: バニラの `MapItem#update` をそのまま呼ぶ (更新半径は 128 ブロック、ネザーなど天井のある次元は 64。見えるのはクライアントにロード済みのチャンクだけ)。更新半径に掛かる地図を 1 tick に 4 枚ずつ回す (近い順。バニラは手に持った地図 = 最大 2 枚/tick だけを更新するので、その 2 倍)。探索していない場所は、バニラのチェッカーの下地 (灰色) のまま
- **操作** (Google マップ風): 既定は**プレイヤーを中心に追従**。ドラッグすると追従を解き、「現在地へ」で戻る。ホイール / 右下の +/- / ダブルクリックでズーム (追従していないときはカーソル位置を中心に)。ドラッグを離すと少し慣性で流れる。**表示できる範囲は、自分のいる最大スケール (スケール 4) の地図の中心から地図 1 枚分の幅 (±2048 ブロック) まで**
- **目印とピン**: 自分の矢印・ピン・構造物・旗は、すべて**バニラの装飾**として、バニラの地図レンダラーが描く (矢印は窓の外に出ると、バニラと同じく縁の「地図の外」アイコン)。
  - **構造物 (シングルのみ・自動)**: バニラの地図にアイコンがある構造物 — 森の洋館・海底神殿・村 5 種・トライアルチャンバー・古代都市・砂漠の神殿・ジャングルの寺院・ウィッチの小屋・暖かい海の遺跡・廃坑・廃墟のキャンプ — を、**プレイヤーが構造物の範囲に 96 ブロックまで近づいたとき**に「発見済み」にして、地図に出す (遠くのものは出ない = ネタバレしない)。一度発見したものは記憶して保存する。配置のデータはサーバー側にしか無い (マルチのクライアントには送られない) ので、**マルチでは自動表示できない** — 手動のピンで置く
  - **旗 (自動)**: ロード済みのチャンクにある旗 (バナー) を見つけて、位置を記憶して地図に出す。旗の色はバニラと同じ 16 色のアイコン、名前を付けた旗は名前も出る。チャンクが読み込まれていて旗が無くなっていれば、バニラの `checkBanners` と同じく目印を消す。バニラの地図は、旗を「地図を持って右クリック」したときだけ目印にするが、この Mod には地図アイテムが無いので、見つけたものを自動で出す
  - **ピン**: 手動。アイコンは**バニラの地図のもの**から選ぶ — マーカー 5 種 (赤・青のマーカー、×、点)、**構造物の場所 15 種**、**旗 16 色**。名前はアイコンの下にバニラが描く。**ピンは保存しない** (そのワールドで遊んでいる間だけ覚えている)
- **画面の見方**: 文字だけの表示や、押しても何も起きないボタン、縮尺バー、北のコンパスは置かず、**地図の上のカーソルの横のツールチップにまとめた** (見出し「ワールドマップ」・カーソル位置の座標と Y・自分のいる座標・ディメンション名・縮尺・操作方法 4 つ。ドラッグ中は出ない)。**左の欄 = 地図の操作**: + / − (ズーム。ホバーで「拡大」「縮小」) / 現在地へ / 完了 / 広域スキャン (条件が合うときだけ。設定は無く自動で出る)。**右の欄 = ピンの機能だけ**: 現在地にピン / 前のピン・次のピン / (ピンを選んだときだけ) 名前・アイコン変更・テレポート・削除 / ピン一覧 (アイコン付き、クリックでそのピンへ移動。画面の高さに収まる行数まで)。選んだピンは地図上で枠が付く
- **全画面表示**: 左上の「**全画面**」ボタン (左の欄の一番上) で、地図を画面いっぱいに拡大する。もう一度同じ位置の「全画面を終了」で戻る。**左右の欄 (ボタン・ピン一覧・広域スキャン) は全画面でも消さず、地図の上にそのまま重ねて出す**ので、全画面のままピンの編集・テレポート・広域スキャンもできる。拡大は、バニラの手の描画の視野角 (`Camera#calculateHudFov` の 70°) を、地図が**画面全体を覆う**まで狭めるだけで行う (`MixinCameraMapFullscreen` / `HandMapGeometry`。16:9 で約 33°)。地図は正方形なので、横長の画面では左右の端が画面の左右の端に接し、地図の上下は画面の外に出る (見える範囲は横が地図の全幅、縦はその一部)。縦長の画面では、地図の下端が画面の下端に接するところまで拡大する。全画面のときは、バニラが描く地図の下地 (紙の枠・縁取り・チェッカー) も描かない。未探索の部分は地図の画像の側で暗い灰色に塗るので、後ろのワールドは透けない。両腕も描かない (地図だけが画面に出る。`MixinFirstPersonHandsAndItemsRenderer`)。状態は `options.txt` の `neo_map_fullscreen` 行に覚える (設定画面には出さない。既定は通常表示 = 行なし)
- **ピン操作 / テレポート**: 右クリックでピンを置く (探索済みの場所のみ) / ピンをクリックで選択 / 右の欄のボタンで「現在地にピン」「前後のピン」(「現在地へ」は左の欄)。**Ctrl+左クリック**でその地点へテレポート。`/tp @s x y z` を送るだけなので、使えるのは権限のあるプレイヤー (OP / チート有効) のみ。高さが分かる (チャンクがロード済み) ときは 1 回で移動。分からないときは最高高度へ移動 → チャンクが来たら地面へ降りる 2 段階 (天井のある次元では断る)
- **保存** (下の「データ保存の共通規約」): バニラの地図データは**バニラの階層・形式のまま** `<ワールド>/data/minecraft/maps/<id>.dat` に置く。この Mod 固有の**索引**は `data/neo/map/index.dat`、**発見した構造物と見つけた旗**は `data/neo/map/markers.dat`。30 秒ごと・ワールドを離れるとき・ゲーム終了時に保存。マルチはワールドのフォルダが無いので、`gameDir/neo/<サーバー>/data/` に同じ構造を作る。ID はこの Mod の索引のカウンタから採番する (`1000000` 以上。バニラの `last_id.dat` は触らない)
- **制限**: 更新できるのはロード済みのチャンク (描画距離内) だけ。過去の探索は引き継がない (機能を ON にした時点から、各スケールの地図に蓄積)。Forge 版 (`src/forge`) には未接続。手の位置は、持ち替えの動きの最中・歩いている揺れ・ダメージの揺れでわずかにずれ、その間は地図上のクリック位置が少しずれる
- **OFF のとき**: 更新・保存・描画をせず、tick では設定を 1 回引いて戻るだけ (M キーの押下も捨てる)。手持ちの差し替えは、画面を開いている間だけ有効 (閉じていれば各フックは「開いているか」の真偽値を見るだけ)

- **広域スキャン (設定なし・シングルで、そのワールドのコマンドの使用 (チート) が ON のとき自動)**: シングルプレイのワールドで「コマンドの使用」が ON のとき、マップ画面の左の欄に「**広域スキャン**」のボタンが 1 つ自動で出る (OFF のときは出ない。クリエイティブである必要はない。設定画面には項目を置かない)。押すと、**いま地図に表示している範囲** (ズームの縮尺に合わせた四角。スケール 0 で 512 ブロック四方、スケール 4 で 8192 ブロック四方) の地図を、内蔵サーバーで一括で作る (もう一度押すと停止)。**ボタンにカーソルを乗せると、範囲 (ブロック・チャンク・地点の数) と予想時間が出る**。予想時間は、初回は 1 秒あたり 1 地点 (新しい 64 チャンクほど) という**目安**で、実行すると実測した速さで更新し (ボタンの下の「残り約 …」も実測)、次回の見積もりにも使う (ゲームを起動している間だけ覚える)。
  - 仕組み: 内蔵サーバーで、地点ごとに周囲のチャンクを「読み込みのみ (ティックしない)」で保持し (未生成なら**生成する**)、読み込めた地点で、バニラの `MapItem#update` をサーバーのレベルに対して実行する。地図はバニラと同じ全スケール (0〜4) に、通常の蓄積と同じ升目・同じ保存 (ID 採番・.dat) で入る。表示中の範囲の中心から外へ向かって順に進み、マップ画面に「N / M 地点 (xx%)、残り約 …」を出す。止めると、ここまでの分は保存される
  - 時間と容量: 範囲は表示中のズームで決まる。読み込むチャンクの数は、**スケール 0 (512 ブロック四方) で約 3 千、1 で約 7.6 千、2 で約 2.3 万、3 で約 7.8 万、4 (8192 ブロック四方) で約 28.6 万** (地図のぶんの余白を含む計算値。天井のある次元は地点が多くなる)。未探索のチャンクは生成するので、時間とディスク容量がかかる。**予想時間はボタンのツールチップに出す**が、初回の速さ (1 秒に 1 地点) は**未測定の目安**で、実行すると実測値に置き換わる。1 tick に使う計算時間は 12ms までに抑えてあるが、スキャン中はゲームが重くなる
  - 制限: シングルプレイのみ (マルチは、サーバーがチャンクを送らないため不可)。そのワールドのコマンドの使用 (チート) が ON のときだけ使える (OFF のときは出ない / 止まる。ゲームモードは問わない)。スキャン中はマップ画面を閉じても続く (進み具合はマップ画面に出る)。ワールドを離れると止まる (そこまでの分は保存済み)。Forge 版には未接続
## 古い環境での動作 (縮退起動)
本体は Java 25・Minecraft 26.3 専用です。**古い Minecraft / Java / ローダー (Fabric・Forge) でも、ゲームを止めずに、ログだけ書いて機能を無効にします** (Java 8 以上)。
- 仕組み: ローダーが最初に呼ぶ入口だけを、Java 8 のバイトコードで作った `neo.compat` (`FabricGate` / `ForgeGate`) に置いてあります。環境 (Java 25 以上 かつ Minecraft 26.3 以上) が合うときだけ本体を呼びます。合わないときは何もせず、`mods/NeoMods.log` に「無効にした / ローダー・Minecraft・Java の版 / 必要な環境」を書きます (最新の起動 1 回分を上書き)。Minecraft の版が分からないときは、Java だけで判断します (25 以上なら動かします)
- そのため `fabric.mod.json` には `depends` (minecraft / java) と `mixins` を書かず、Mixin の設定 (`mixins.neo.json`) は Fabric の入口 (`preLaunch`) が、環境が合うときだけ登録します。Forge の `mods.toml` にも Minecraft の版の依存はありません。Forge の `@Mod` は `ForgeGate` にあります
- 制限: 古い環境でも、**本物の Mod Menu と一緒には使えません** (この Mod は `modmenu` を `provides` しているため、ID が衝突します)。古い環境での動作は、ローダー本体の仕様に依ります (試験は、偽のローダーを使った入口の動作確認まで)


## データ保存の共通規約
この Mod が持つ**ワールド (サーバー) ごとのデータ**は、次の規約で保存します (`neo.data.NeoData`)。新しい永続データを足すときも、このクラスを通します。

```
<ワールド>/data/                     バニラのワールドの data フォルダ (シングル)
  minecraft/maps/<id>.dat             バニラのデータは、バニラの階層・形式のまま置く
  neo/<path>.dat                      この Mod 固有のデータ (索引など) は、必ず neo/ の下
```
- 形式はバニラの SavedData と同じ gzip の NBT で `{ DataVersion, data: {...} }`。`path` は小文字・数字・`/ . _ -` だけ (例: `map/index` → `data/neo/map/index.dat`)。一時ファイルに書いてから置き換えるので、途中で落ちても壊れない
- 設定は**バニラの `options.txt`** に `neo_<キー>:<値>` の行で保存する (例: `neo_zoom:true`。`config/modmenu.json` は使わない)。ワールドごとのデータは置かない。Forge 版は対象外 (設定は保存されない)
- 例外: `mods/NeoMods.log` は起動ログで、データではない

## ズーム (素手で右クリック長押し)
`neo.zoom` + `MixinCameraZoom` / `MixinMouseHandlerZoom`。動作は Wurst Client 由来の **WI Zoom** (参考: `WI-Zoom-1_5-MC1_20_4.jar`) と同じです。
- **両手が空のとき右クリックを押している間**ズーム (離す・物を持つ・画面を開くと戻る。専用キーは無し)。視野角を倍率で割る。既定の倍率は **3 倍**
- **押し始めて 0.25 秒たつまではズームしない** (単押し・素早いクリックでは動かない。通常の右クリック操作はそのまま)
- 視野角は一気に切り替えず、**バニラの望遠鏡と同じ方式でなめらかに寄る/戻る** (1 tick ごとに目標との差の半分を詰める。経過時間で計算するのでフレームレートに依存しない)。ホイールで倍率を変えたときも滑らかに追従する
- ズーム中は**視点移動の感度も下げる** (マウス感度の設定値 × 1/倍率。設定値そのものは書き換えない)
- ズーム中の**ホイール**で倍率を ×1.1 (奥へ) / ×0.9 (手前へ)、1〜50 倍。ホットバーは切り替わらない。倍率は右クリックを離すと 3 倍に戻る
- 手の描画の視野角 (hudFov) は変えない (WI Zoom と同じ)。画面を開いているときはホイールを横取りしない
- **OFF のとき**: Mod Menu の設定 `zoom` が OFF なら、視野角・感度・ホイールのどれも触らない (各フックで設定を 1 回引いて戻るだけ)
- **WI Zoom との違い**: キーが V → **素手の右クリック長押し**、視野角はバニラの描画用メソッドが 26.3 で `Camera#calculateFov` に変わったのでそこへ注入、感度は設定値を書き換えず `MouseHandler#turnPlayer` の読み取りに掛ける (WI Zoom は設定値を書き換えて後で戻す)
- **ライセンス**: WI Zoom は GPL-3.0-or-later。ここでは動作だけを参考にして独自に実装しており、コードは取り込んでいない

## 画面の直接切り替え (既定 ON)
`neo.advancements.ScreenSwitch` + `MixinAdvancementsScreenSwitch` / `MixinAbstractContainerScreenSwitch` / `MixinBookViewScreenSwitch` (+ `neo.map.WorldMapScreen` の `keyPressed`)。
- バニラは進捗画面もインベントリ画面も「自分を開くキー」でしか閉じず、相手のキーは無視する。26.3 の `AdvancementsScreen#keyPressed` / `AbstractContainerScreen#keyPressed` を読んで確認
- 進捗画面で**インベントリのキー**を押すと、バニラの「インベントリを開く」と同じ手順 (`isServerControlledInventory` ならサーバー経由、そうでなければ `InventoryScreen`) で開く
- 次の画面で**進捗のキー**を押すと進捗画面が開く: インベントリ (サバイバル / クリエイティブ) を含む**すべてのコンテナ画面** (チェスト・エンダーチェスト・シュルカーボックス・作業台・かまど系・金床・取引・醸造台・エンチャント台・馬のインベントリなど = `AbstractContainerScreen` の全サブクラス)、**本の閲覧** (教卓を含む)、**ワールドマップ**。入力欄 (レシピブック・クリエイティブの検索欄・金床の名前欄・マップのピン名欄) がキーを使ったときは切り替わらない (キー処理の末尾で、キーが使われなかったときだけ判定)
- 対象外: 文字入力が主の画面 (チャット・看板・本の編集 / 署名・コマンドブロック・ストラクチャーブロックなど)、ポーズ画面・オプション画面 (キー割り当て中に誤爆するため)
- メニューを持つ画面 (コンテナ画面・教卓) から切り替えるときは、バニラの `onClose` と同じく**サーバーにコンテナを閉じたことを送る** (`LocalPlayer#closeContainer`)。送らないと、チェストなどがサーバー側で開いたままになる
- 新しいキーは作らない (バニラの `keyInventory` / `keyAdvancements` をそのまま使う)。進捗画面に「戻り先」は付けない (L / Esc でゲームへ戻る)
- **OFF のとき**: 設定 `screen_switch` が OFF ならバニラと同じ

## インベントリ移動 (既定 ON)
`neo.invmove` + `MixinGuiInventoryMove` / `MixinKeyboardHandlerInventoryMove` / `MixinKeyMapping` (キー割り当ての窓口)。
- バニラが止める理由は 2 つ: 画面を開くとき `KeyMapping.releaseAll()` で全キーを離した扱いにする / 画面が開いている間はキーを押しても押した扱いにしない。26.3 の `Gui#setScreen` / `KeyboardHandler#keyPress` を読んで確認。プレイヤー側 (`KeyboardInput#tick`) は画面の有無を見ないので、押下状態を保つだけで歩き続ける
- 対象のキー: 前・後・左・右・ジャンプ・ダッシュ。**スニークは対象外** (Shift クリックでしゃがんでしまうため)。ダッシュが**トグル**設定のときはバニラのまま (画面を閉じると元に戻る)
- 対象の画面: コンテナ画面 (インベントリ・チェスト・作業台・クリエイティブなど)。チャット・看板・本などの文字入力画面と、文字入力中の入力欄 (クリエイティブ/レシピブックの検索欄・金床の名前欄) は対象外
- マウスで視点は回せない (画面を開くとカーソルが解放されるバニラの仕様のまま)
- **OFF のとき**: 設定 `inventory_move` が OFF なら、各フックで設定を 1 回引いて戻るだけ (バニラと同じ)
- マルチサーバーによっては、画面を開いたまま動く挙動をアンチチートが検知することがある

## F5 の自由視点 (既定 OFF)
`neo.freelook` + `MixinMinecraftFreeLook` / `MixinMouseHandlerFreeLook` / `MixinCameraFreeLook`。動作は **Perspective Mod 3.0** (1.8.9、参考: `_1_8_9__Perspective_Mod-3_0.jar`) と同じです。設定 `free_look` を ON にしたときだけ、F5 の長押しが自由視点になります (OFF の間は F5 はバニラのまま)。
- **F5 を長押し** (0.25 秒より長く押し続ける) すると三人称 (背面) の自由視点になり、**マウスで回るのはカメラだけ**。プレイヤー自身の向きは変わらない (同じ方向を向いたまま、周りを 360 度見回せる)。攻撃・設置などの狙いもプレイヤーの向きのまま
- **F5 を離す**と、押す前の視点 (一人称など) に戻る
- **F5 の単押し** (0.25 秒以内に離す) は**バニラの視点切り替え** (一人称 → 背面 → 前面) を 1 回だけ行う。離した時点で切り替わる
- 自由視点の向きは、押した時点のプレイヤーの向きから始まる。上下は ±90° まで
- 自由視点中は、バニラの切り替えの書き込み (`Options#setCameraType`) を独立に止める (自由視点中にバニラの切り替えが走らないようにする保険)
- 一人称 ↔ 三人称の切り替え時に、バニラと同じ後処理 (スペクテイターのシェーダー効果の付け外し) を行う
- **OFF のとき**: `handleKeybinds` の F5 の判定で設定を 1 回引いてバニラの結果を返すだけ。マウス・カメラのフックは「自由視点中か」の真偽値を見るだけ (設定も引かない)
- **Perspective Mod との違い**: 設定の保存は Mod Menu の設定 (`options.txt` の `neo_` 行)、モード切り替えは専用コマンドではなく設定画面。別のキーではなく **F5 そのものの挙動を変える**
- **ライセンス**: 参考にした jar のコードは取り込んでいない (動作だけを参考に独自実装)

## 3D スキンレイヤー (既定 ON)
`neo.skinlayers` + `MixinModelPartSkinLayer` / `MixinPlayerModelSkinLayer` / `MixinAvatarRendererSkinLayer` (本体と一人称の手) と、頭用の `MixinSkullBlockRendererSkinLayer` / `MixinSkullBlockRenderStateSkinLayer` / `MixinPlayerHeadSpecialRendererSkinLayer` / `MixinCustomHeadLayerSkinLayer` / `MixinSkullModelSkinLayer` / `MixinSkullModelStateSkinLayer`。設定 `skin_layers` が ON の間だけ働きます (OFF にするとバニラのまま。スイッチはこの 1 つだけ)。

- **対象**: プレイヤーの帽子・上着・左右の袖・左右のズボンの 6 レイヤー (ワイド/スリム両対応) と、一人称の手の袖。さらに**プレイヤーの頭**の帽子の層も立体にする: 設置した頭ブロック (壁掛けも)、頭アイテム (インベントリ/GUI・手・地面・額縁)、頭に被っているとき (プレイヤー・ゾンビなど)。ゾンビ・クリーパーなど他の頭と、Deadmau5 の耳 (耳のモデルは、立体にもせず、メッシュも付けない) は対象外
- **立体にする方法**: スキンの不透明なピクセル 1 つを、小さな立方体 (ボクセル) にして描く。厚さはバニラのレイヤー面から内側 0.5px・外側 0.4px (外側を 0.5px にすると、帽子の外面がヘルメットと同一平面になって Z-fighting するため)。バニラのレイヤー用 Cube の面・UV・頂点の向きをそのまま読み取って作るので、向きやミラーを決め打ちしない。内側 (体に隠れる側) と、隣も不透明な側面は作らない。HD スキン (64 の倍数) も可。
- **頂点数の削減 (見た目は変えない)**: ① 外側の面は、不透明なピクセルの長方形ごとに 1 枚にまとめる (貪欲法。UV はスキン上の実際の範囲を与える) ② 側面は、隣り合うピクセルが同じ色なら 1 枚にまとめる ③ 面の境目 (角) の側面は、隣の面のボクセルに半分隠れて半分は見える (角を埋める) ので省かない。1 体分の四角形は、全面不透明のスキンで 約 2,656 枚 → 約 180 枚、色や穴の多いスキンでも約半分になる (検証用の模様での値。下記 REFACTOR_NOTES)旧形式 (64x32) は対象外 (レイヤーが無い)
- **遠いと 2D に戻す**: カメラから 16 ブロックより遠いプレイヤー・頭ブロック・被っている頭は、バニラの 2D のまま (固定値)。頭アイテム (GUI・手など) はカメラからの距離を持たないので、距離では切らない
- **メッシュはスキンごとに作ってキャッシュ** (最大 384 個、古いものから捨てる)。OFF にするとキャッシュを捨てる。スキンの読み込み前など、一時的に作れなかったものは 5 秒後にやり直す
- **参考にしたもの**: 3D Skin Layers 1.11.3 (tr7zw Protective License: 商用利用・金銭的利益の禁止、著作権表示の同梱が条件)。**コードは取り込んでおらず**、動作 (レイヤーのボクセル化、距離による 2D への切り替え) だけを参考にした独自実装。Fabric API・TRansition・TRender (Sentry を含む) は使わない
- **対応していないもの**: ボクセルの大きさ・距離の設定 (固定値)、Sodium/Iris 向けの回避策

## AFK シネマティック (既定 ON)
`neo.cinematic` + `MixinCameraCinematic` / `MixinHudCinematic` / `MixinKeyboardHandlerCinematic` / `MixinMouseHandlerCinematic`。動作は **Ji AFK Cinematic 2.3.1** (MIT、作者 jiory_) を参考にした**独自実装**で、コードは取り込んでいない (音楽とキー割り当ては持たない)。
- F1 の扱い: **F1 で GUI を隠した状態で、もう一度 F1** を押すと、GUI を出さずにシネマティックになる。**シネマティック中に F1 を押すと、シネマティックが終わって GUI が戻る** (放置で始まった場合も)。設定 OFF のときは、バニラどおりの F1
- 開始: 画面を開いていない状態で、キー・マウス (移動・ボタン・ホイール) の操作が **30 秒 (600 tick)** 無い。画面を開いている間は放置と見なさない
- 演出: 視点を三人称にし、HUD を F1 と同じ仕組みで隠し (チャットは残す。F1 の扱いは上)、上下に黒帯 (2.1:1。16:9 の画面で上下それぞれ高さの約 7.7%) を出す。カメラは 10 秒ごとにカットを切り替える (プレイヤー中心 6 種: 低い位置から回り込む・上から回り込む・寄る/引く・足元から顔へ・横を並走・肩越し / 景色中心 6 種: 見回す・水平線・上昇・空を見上げる・横へ滑る・遠くから大きく回る。1 巡 = プレイヤー中心 3 + 景色中心 7 で、同じカットは続かない。巡が終わると新しく並べ直す)。壁があれば手前に寄る
- 釣り中 (浮きが出ている間): 通常どおり始まる。見る点をプレイヤーと浮きの中間にし、カメラと中間の距離を「浮きまでの水平距離 × 0.75 + 3 〜 +6」に保って、浮きが画面に入るようにする (カットの回り込みなどの動きはそのまま)
- カメラの上書き: `Camera#alignWithEntity` の末尾で位置と向きだけを変える。プレイヤー自身の位置・向きは変えず、サーバーへも何も送らない
- 終わる: キー・マウスの操作 / 画面が開く / ダメージ / 死亡 / 設定を OFF / ワールドを離れる。終わると元の視点と HUD に戻る。**ダメージと死亡で止まったときは、次の操作があるまで再開しない**
- OFF のとき: 毎 tick 設定を 1 回引いて即 return。入力のフックは状態変数を見るだけで戻る

## Mod 一覧画面のタイトル
左上のタイトルは「Mod Manager」(下線つき)。カーソルを重ねると「説明：読み込まれているMODを管理するNeoModsの機能」とツールチップが出ます (`modmenu.screenTitle` / `modmenu.screenTitle.tooltip`)。タイトル画面・ポーズ画面の「Mods」ボタンの文言 (`modmenu.title`) は従来どおり「Mods」です。

タイトル画面の言語ボタンの並び (`modify_title_screen` が ON のとき) とポーズ画面のアイコン列 (`modify_game_menu` が ON のとき) には、Mods のアイコンボタンが並びます。押すと **NeoModsの設定画面** (`modmenu.options`) が開きます (Mod 一覧ではありません)。@ キーも同じ設定画面を開きます。

タイトル画面のアイコン列 (`modify_title_screen` が ON のとき) には、Mods アイコンの右に **Discord アイコン** (`neo.discord`「Discord に参加」) も並びます。押すと Discord の招待リンク (`SmallModManagerButtonWidget.DISCORD_URL`) を開きます (「クリックの確認を省略」が ON の既定では確認画面なしで直接開き、OFF のときは確認画面を経ます)。画像は `textures/gui/sprites/discord/` の **16x16 のカラー** (3 状態とも同じ。Discord のブランド色 `#5865F2` の角丸の下地に白いロゴ。ドットで手描き) で、ボタンの中央に等倍で描きます。色は discord.com/branding のブランド色、ロゴの形は Simple Icons (CC0) の Discord を参考にしました。差し替えるときは、同名の PNG にしてください。

## サウンドブラウザ (クリエイティブ)
`neo.sound`。クリエイティブインベントリの右側面に縦向きのタブ (音符ブロック) を 1 つ足します (バニラの 14 枠は変えない。Fabric API のページ送りは使わない)。
見た目はバニラのスプライトだけで作る: タブ = レシピ本の横向きタブを左右反転、枠 = ポップアップの枠 (`popup/background`)、一覧 = スロットと同じくぼみ、スクロールバー = クリエイティブのもの、選択中の音 = 「Now Playing」トーストの枠 (`toast/now_playing`。再生中は動く音符 `icon/music_notes`)。
- 画面: 画面いっぱいを使い、幅があれば左に一覧・右に操作の 2 列 (狭いときは一覧の下に操作を 2 行)
- 一覧: ゲームが**実際に読み込んでいる**サウンドイベント (`SoundManager#getAvailableSounds`。リソースパック・他 Mod の音を含む) を、名前空間 → ID を `.` で区切った階層の木で表示。画面を開くたびに作り直すので、F3+T の再読み込みも反映される
- 字幕: 各音に、バニラの**字幕** (アクセシビリティ設定の「字幕」で出る音声の説明。`sounds.json` の `subtitle`、現在の言語) を右に添えて表示。字幕の無い音は名前だけ
- 検索: ID または字幕の部分一致。検索中・「お気に入りのみ」のときは該当する階層を自動で展開
- 試聴: ピッチ (0〜2。`/playsound` と同じ範囲。サウンドエンジンが 0.5 未満を 0.5 に丸めるため、0.5 未満は 0.5 と同じ音)・音量 (0〜1)・カテゴリを指定し、**自分のクライアントだけ**で鳴らす (サーバーへは送らない)。行のダブルクリックでも再生
- コピー: `/playsound <ID> <カテゴリ> @s ~ ~ ~ <音量> <ピッチ>` をクリップボードへ。コマンドブロック用に先頭の `/` なしでもコピーできる
- お気に入り: 行の右端の ☆ をクリック。`options.txt` の `neo_sound_favorites` 行 (「,」区切り) に保存
- OFF のとき: クリエイティブ画面を開いたときに設定を 1 回引くだけで、タブも一覧も作らない
